Sanity CTBR pitch-loop MPC — simulation only

Purpose
Develop the existing trajectory-to-CTBR MPC formulation into a full-attitude
pitch-loop controller and test it in the native loco_mjx MJX plant before
considering deployment. No ROS, Zenoh, ESP or flight-controller access exists
in this runner. The deployed upright MPC and firmware remain unchanged.

Reference
p(phi) = [a sin(phi), 0, z_bottom + b(1-cos(phi))].
Initial baseline a=0.50 m, b=0.65 m, z_bottom=0.50 m:1.0 m width,1.3 m height,
reference top1.80 m. Phase cruise rate5.71949 rad/s (~1.10 s per loop).
Quintic speed ramps of0.65 s give zero acceleration/jerk at hover boundaries.
Two seconds initial hover, then requested loops, then four seconds recovery.
The selected higher-clearance preset uses a=0.476923 m,b=0.62 m,top1.74 m,
phase rate5.856231 rad/s and thrust-command cost0.1 (initial0.01).
Its reference pitch-rate peak is8.69 rad/s,lag-inverse command peak8.93 rad/s.
Positive-thrust reference F=m*|p_ddot+g*e_z|; pitch=unwrap(atan2(F_x,F_z)).
Pitch is derived from acceleration+gravity, never set equal to ellipse phase.
The same ellipse is used through entry/exit; there are no extra path lobes.

Controller
Acados SQP_RTI/HPIPM,20nodes*40 ms, two RTI passes per50 Hz command.
State14: world position3, body-to-world quaternion wxyz4, world velocity3,
body angular velocity3, collective force1. Input4: thrust N and body rates rad/s.
Model: p_dot=v; q_dot=0.5*q*[0,omega];
  v_dot=R*e_z*F/m-g*e_z;
  I*omega_dot=torque_servo_with_rotor_headroom - omega cross I*omega;
  F_dot=(command-F)/tau_up_or_down.
Tau_up/down43.8819/48.5511 ms; rate servo and torque headroom use the same
provisional parameters as the pinned plant. The simulator includes its native
implicit servo and air drag. MPC prediction omits that passive aerodynamic drag.
Inputs are optimized directly; no CTBR slew/output filter is applied.
Simulation bounds:T<=2.85 N, roll/pitch/yaw rates<=2.3/9.5/2.6 rad/s.
The 9.5 rad/s pitch bound is a SIMULATION-ONLY extrapolation, NOT an identified
high-rate actuator model. Current deployed host/ESP pitch bound remains2.3 rad/s.
The nominal reference needs ~8.49 rad/s (~486 deg/s), with ~8.71 rad/s lag-inverse
feedforward.600 deg/s FC scaling alone does not establish high-rate controllability.

Accepted command contract
Finite control and nonlinear rollout; successful RTI/QP status; raw input
violation<1e-4; nonlinear predicted height violation<1e-4; full computation<=25 ms.
No claim that RTI status0 means a converged nonlinear optimum. Diagnostics record
raw-vs-nonlinear-rollout disagreement and nonlinear residuals. Simulation trial
limits are root height0.15..2.0 m and horizontal radius2 m; every trajectory starts
around0.5 m.0.5 m is the starting/reference bottom height, not a strict actual floor.

Causal observations and known delay
The pinned mocap model samples poses, differentiates and filters velocity/rates,
and selects a causal state. In causal mode the controller receives this state,
not truth or true force. It approximately inverts the known derivative filter
using model acceleration, maintains force estimates from command history, and
propagates through observation age and the known queued command delay.
No future physical state is supplied. The exact known-delay assumption is part
of the test: it does not establish tolerance to unknown latency/jitter.
'applied_command' in traces denotes input after the explicit fixed queue; any
optional training delay occurs inside the physical plant afterward.

Plant and provenance
plant.py reuses the pinned SanityPlantEnvironment.advance implementation in
outputs/sanity_pitch_flips_hover_20261021/source. It loads no learned policy.
MJX runs4x5 ms substeps per50 Hz command, calibrated delivered-FC-voltage thrust
conversion, firmware fixed-point/integer RC mapping, calibrated yaw allocation,
collective-dependent torque headroom, implicit servo and passive air drag.
plane.xml, Acro100 profile, FC-voltage profile and yaw-reaction calibration match
byte-for-byte the response_tracking_20261021_long training snapshot. This does
not imply identical entire training randomization or observation configuration.
Chosen-voltage and sampled model/lag parameters are recorded for each episode.

Separate uncertainty factors

  and jitter, while collective lag stays nominal unless also requested.
--random-actuator-lag: additionally sample the training collective-response lag
  variation, while random command delay stays disabled unless also requested.
Both flags reproduce the coupled timing stress in the earlier training default.

collective lag. Removing that component also removed lag variation. Assessment
must distinguish the nominal-lag parameter suite from full timing/lag stress.

Files and evidence
Each run saves configuration, native worker log, summary and every recorded
trial. Success requires actual body pitch turns, independent measured path

Deployment boundary
This is an experimental simulation extension, not a flight-ready flip mode.
The live interface still clips pitch at2.3 rad/s and its upright tilt monitor
rejects inversion. High-rate servo response, thrust/torque headroom, inverted
mocap visibility and uncertain communication delay need real validation.
A dedicated flip mission/recovery/command-freshness monitor is required before
any real flip attempt; the current one-second command lease is not qualified
for a maneuver needing ~500 deg/s pitch rates. No fly command is provided here.
